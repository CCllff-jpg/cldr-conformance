我在写一个 CLDR 一致性对拍工具（[cldr-conformance](https://github.com/CCllff-jpg/cldr-conformance)），跑 CLDR 官方的 `decimals.tsv` 时发现下面这个问题，附最小复现。
**版本**：`zlhahaha/moonlocale@0.1.0`
**严重性**：高——**静默给出错误结果**，不抛异常

## 现象

```moonbit
let ar = @moonlocale.Locale::from_string("ar").unwrap()
let formatter = @moonlocale.DecimalFormatter::new(ar)
formatter.format_percent(
  @moonlocale.Decimal::new(1234565, 0),
  @moonlocale.PercentSpacing::LocaleDefault,
)
// 实际: "-1٬097٬551٫584%"
// CLDR decimals.tsv（ar, percent, 1234565.0）期望: "123,456,500%"
```

不是"格式不对"，而是**数值本身算错了**：符号变成负、量级也不对。

## 根因

`decimal.mbt:191` 的 `decimal_digit_parts` 把定点系数**放大成整数**再取十进制串：

```moonbit
let expanded = positive_int(rounded.coefficient) *
  power_of_ten(visible_scale - rounded.scale)
let raw = expanded.to_string()
```

代入本例：`1234565`（系数）× `100`（百分比）× `10^3`（默认最大小数位）= `123,456,500,000`，
超出 `Int`（2^31−1 = 2,147,483,647）后回绕：

```
123450000000 + 6500000 = 123,456,500,000
123,456,500,000 mod 2^32 = 3,197,415,712
按有符号 32 位解释          = -1,097,551,584
→ 输出 "-1,097,551.584"
```

（与实测输出完全吻合。）

## 触发条件

任何满足 `|coefficient| × 10^(max_fraction − scale) > 2^31−1` 的值。
默认 `max_fraction = 3` 时，绝对值 ≳ **2,147,483.648** 的数字就会出错；
百分比模式先乘 100，阈值再缩小 100 倍（约 21,474.84）。

`Decimal::times_int` 本身没问题（`1234565 × 100 = 123,456,500` 未溢出），
问题出在**格式化时**把系数放大到整数空间。

## 建议

1. 不要用 `Int` 放大：直接按十进制串拼接（把小数点插在 `scale` 位置），
   或改用 64 位整数/字符串算法；
2. 若坚持用 `Int`，至少在 `expanded` 计算前检查上界并**返回错误或饱和值**，
   而不是静默回绕——错误的数字比报错更危险。

## 影响面

CLDR 数字套件里 **103 条**用例（所有 locale 的百分比大数用例）落到
`value-mismatch` 归因；这是本轮对拍里占比第三的失败类别。
